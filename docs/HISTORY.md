### H1. Приватный VAPID-ключ лежал в публичном коде
**До 2026-11-09 · до истории git (аудит 2026-11-09)**
- *Симптом:* в `server/services/notificationScheduler.ts` был зашит запасной ключ `DEFAULT_VAPID_KEYS`.
- *Причина:* «запасной вариант на всякий случай» в публичном репозитории = скомпрометированный ключ.
- *Исправление:* сгенерирована новая пара; ключи только из секретов репозитория `VAPID_PUBLIC_KEY`/`VAPID_PRIVATE_KEY`; в CI/проде без них код падает (`getOrGenerateVapidKeys`); публичный ключ кладёт в `dist/state/vapid-public.json` workflow деплоя; `*vapid-keys.json` в `.gitignore`. Ротация ключей сделана (по записям плана работ). По старому HANDOFF приложение само пересоздаёт подписку при смене ключа — на устройстве это не проверялось.
- *Правило:* никаких ключей и запасных секретов в коде.

### H2. Подписки и адреса — в публичном репозитории
**2026-11-09 · PR #5**
- *Симптом:* `state/subscriptions.json` (push-endpoint, ключи `p256dh`/`auth`, адреса) коммитился в публичный репо; клиент писал его через GitHub PAT из `localStorage`.
- *Причина:* git использовался как база данных.
- *Исправление:* Worker `svitlo-subs` + приватный Cloudflare KV; регистрация по коду-приглашению, токен записи на каждое устройство, `/internal/*` только с `SUBS_SECRET`; push-check читает список оттуда и падает громко, если хранилище недоступно; PAT-путь удалён (приложение стирает старый токен). Улица/дом не покидают телефон.
- *Остаток:* старое содержимое осталось в истории git и в `refs/pull/*/head` (удаление — только через GitHub Support); владелец пересоздал подписку, старый endpoint недействителен. В публичном журнале `state/schedule-snapshot.json` видны случайные id устройств и id адресов (без endpoint'ов и адресов).
- *Правило:* в git — только то, что не жалко показать всем.

### H3. Cron GitHub Actions ненадёжен
**2026-11-09 · PR #1**
- *Симптом:* `push-check.yml` по своему `schedule:` запустился один раз с момента создания → предупреждения «за 30 мин» не приходили.
- *Причина:* встроенный cron GitHub не гарантирует запуск (задержки, пропуски).
- *Исправление:* Worker `svitlo-trigger` (Cloudflare cron) раз в 5 мин вызывает `workflow_dispatch`; собственный `schedule: */10` оставлен запасным (журнал дублей делает двойные запуски безвредными). Серверное окно сужено с 10..42 до 10..32 мин (из коммита: «при 5-минутном триггере широкое окно не нужно»).
- *Правило:* надёжность расписания — внешний триггер. Меняя шаг триггера или окно, проверьте, что каждое событие гарантированно попадает в окно хотя бы одним запуском (окно шире шага с запасом на задержку Actions).

### H4. Деплой запускал рассылку пушей
**До 2026-11-09 · до истории git (аудит)**
- *Симптом:* `deploy-pages.yml` выполнял push-логику. Приходили ли дубли на практике — не установлено.
- *Причина (из комментария в workflow):* деплой слал бы реальные пуши и менял журнал дублей, не коммитя его → следующий cron отправил бы те же пуши снова.
- *Исправление:* деплой вызывает только `npm run sync:schedules` (без пушей и журнала). Push-check коммитит журнал с 4 повторами и падает громко, если не смог.
- *Правило:* пуши шлёт только `push-check.yml`.

### H6. «Автоопределение» группы было выдумкой
**2026-11-09 · PR #2, #3**
- *Симптом:* группа «определялась» хешем от адреса — то есть случайно.
- *Причина:* настоящего источника не было; браузер не может звать YASNO напрямую (нет CORS).
- *Исправление:* Worker `svitlo-address` — read-only прокси к адресному API YASNO (улицы → дома → группа), только Киев. Неоднозначность → группа не ставится. Тест «никогда не выдумывает группу» сделан герметичным (без живого сервиса, #3).
- *Правило:* не угадывать; ручной выбор — только запасной путь после неудачи.

### H8. Область: группы нет ни в YASNO, ни через Cloudflare
**2026-11-09…10 · PR #6, #7**
- *Симптом:* для Киевской области автоопределение не работало.
- *Причина:* в YASNO данных области нет (коды операторов 900–910 региона 25 пусты); сайт `dtek-krem.com.ua` закрыт Imperva для IP Cloudflare; с раннера GitHub Actions обычный `curl` проходит (разведка: 0 блокировок в 4 прогонах).
- *Исправление:* Worker `svitlo-lookup` (`/start`, `/result`; KV, TTL 10 мин; суточный лимит `DAILY_LIMIT`; код-приглашение) запускает `dtek-lookup.yml`, раннер забирает задание у Worker'а и отдаёт результат (`scripts/dtek-lookup.ts`, парсер `scripts/dtek/lookupCore.ts`). Адрес никогда не попадает в inputs/логи публичного workflow — только непрозрачный `job_id`. У каждого задания своя `concurrency`-группа (общая молча отменяла бы ожидающие запуски). Ответ 20–90 с.
- *Риски (приняты владельцем):* правила сайта ДТЕК, блокировка IP раннеров, смена разметки → деградация в «не удалось определить».
- *Правило:* публичные логи = публичные данные.

### H11. Кольцо суток не читалось как часы
**2026-11-10 · PR #9 → #12**
- *Симптом:* круг «24 часа» владелец не воспринимал как часы; следующие варианты — «лучше, но сложно».
- *Причина:* глазу приходилось переводить угол во время и угадывать половину суток.
- *Решение (по итерациям):* два кольца 00–12 / 12–24 (#9) → «G+»: толстое кольцо — текущие 12 часов (прошлое приглушено), тонкая дорожка — следующие 12 часов, после 12:00 это завтрашнее утро, пунктир, если не опубликовано (#10) → реальные 24-часовые цифры, метка «завтра · 00», разрыв дорожки на 12 (#11) → цифры 13 вместо 10 единиц viewBox, поле `RING_PAD` (#12). Точное время — числами в центре («до HH:MM») и в списке.
- *Правило:* визуальные решения сначала показывать картинками (390 и 320 px, обе темы), код — после одобрения.

### H14. iPhone обрезает заголовок пуша
**2026-11-10 · PR #15, #16, #17**
- *Симптом:* в заголовке терялись имя адреса и время (`20:00 увімкне…`).
- *Причина:* iOS делит строку заголовка с «N хв тому» и через несколько минут режет до ~14–15 знаков после эмодзи (видно на устройстве).
- *Исправление:* имя адреса — в начало текста (#15); время первым: `🪫 16:00 вимкнення` (#16); короткий `🗓️ Графік змінено`, день — в тексте (#17). Обрезание у пушей возрастом 10+ мин принято как косметика.

### H15. iOS показывал старую иконку
**2026-11-10 · PR #18, #19, #20**
- *Симптом:* после переустановки PWA на домашнем экране старая иконка, хотя на `gh-pages` уже новый файл, а в меню «Поделиться» — новая.
- *Причина:* iOS кэширует иконку по URL.
- *Исправление:* PNG переименованы с суффиксом `-v2`. Источник — `public/icon-192.svg`, PNG рендерятся из него (скриншот Playwright).
- *Правило:* при смене иконки — новый суффикс (`-v3`) и обновить все ссылки (`index.html`, `public/manifest.webmanifest`; проверить `grep -rn "\-v2" index.html public`), старые файлы не перезаписывать.

### H16. «Екстрені відключення» висели после отмены; «було екстрені…»
**2026-11-10 · v18.6.3 · PR #21**
- *Симптом:* приложение показывало экстренные отключения, хотя их уже отменили (пришла SMS ДТЕК). В пуше — «(було екстрені відключення)»: неграмотно и после переноса строки читалось как будто последний интервал — экстренный.
- *Причина:* флаг `EmergencyShutdowns` приходит только из снимка сервера `state/combined-schedules.json`. Клиент брал его из копии на Pages, а она заморожена на момент последнего деплоя (бот коммитит снимки с `[skip ci]`); правило «флаг прилипает к живым данным» держало старую экстренность до следующего деплоя.
- *Исправление:* клиент читает снимок из `main` через `raw.githubusercontent.com`; флаг переносится только из свежей копии (`carryEmergencyFlag`); копия Pages — только запас, если `main` недоступен, и её флаг на живые данные не переносится. Текст: `(замість екстрених відключень)`. Тесты: `tests/emergencyCarry.test.ts` (проверено, что падают на старом поведении), `tests/changeNotification.test.ts`.
- *Правило:* копия на Pages ≠ свежие данные.

### H17. Ссылка-приглашение и установленная PWA на iOS
**2026-11-10 · не исправлено, не проверено**
- *Суть:* ссылка `…/dtek-svitlo-app/#invite=КОД` обрабатывается `loadInviteCode()` (сохраняет код, убирает hash). На iPhone ссылка открывается в Safari, а у установленной PWA, по всей видимости, отдельное хранилище → код может не попасть в PWA. Надёжный путь для знакомого: установить PWA и ввести код вручную в «Сповіщення → Додатково».
- *Что сделать:* проверить на устройстве; если не работает — убрать обещание из инструкций.
